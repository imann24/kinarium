# UI audit and overhaul — 30 October 2026

## Scope and direction

The audit covered the landing/directory, living world, journal/residents/bonds,
community insights, forms, field guide, access gate and admin sign-in in light
and dark themes. The user rejected the prior plum/green treatment and requested
a deep overhaul. The user confirmed keeping the existing house illustrations as the visual
anchor and rebuilding the UI around them. Simulation behavior is preserved.

The replacement uses warm ivory and oat surfaces, olive-charcoal text, forest
primary actions, and pale sage selection states. Manrope carries working
headings and controls; Dela is reserved for the wordmark and landing page.
The detailed palette is an implementation judgment within that confirmed
direction, not a separate user-approved visual mockup.

## Findings and changes

| Finding | Evidence and impact | Resolution |
| --- | --- | --- |
| Competing palettes and heading hierarchy | Large plum/yellow areas competed with muted house artwork; heavy display headings dominated task text. | Replaced shared palette and task typography across both themes. |
| Dark outline hover contrast (P1) | World settings text fell to approximately 1.06:1 on hover because an old selector overrode the theme. | Semantic resting/hover states in explicit cascade layers; browser contrast regression check. |
| Event deck contrast (P1) | Enabled tone labels and Introduce text measured approximately 3.15–3.71:1; whole-card fading further reduced readability. | Contrast-safe tone text and full opacity for enabled cards; larger labels and controls. |
| Mobile reading and action hierarchy (P2) | Header/navigation and a 520px journal delayed events; cramped metrics and repeated framed panels made scanning difficult. | Compact header, adjacent journal control, 340px journal, house-event jump, readable summary rows, stacked insight lists, fewer nested panels. |
| Enlarged-text reflow (P2) | Neighborhood count/heading overflowed at 200% text; later checks exposed long-word and insight-layout overflow. | Wrapping heading/count and long words, corrected responsive declaration order, explicit mobile grids and meter positioning. |
| Small secondary controls (P2) | Deck controls were 30–36px high; repeated disclosures and dialog close controls were small. | Shared 44px close/action targets, 44px event controls and disclosure hit areas. Inline links retain normal text flow. |
| Dialog scroll chaining (P2) | Wheel input at the end of settings moved the underlying world by 1000px. | Contained dialog overscroll and CSS document lock while any native dialog is open. |
| Conflicting style generations (P2) | Historical base rules, theme repairs and app-chrome overrides competed; obsolete directory rules remained. | Explicit base/components/theme/interface layers, semantic token file, removal of obsolete directory selectors and old app-chrome, consolidation of duplicate insights declarations. |

Connection classification rules remain available in a disclosure. Empty
connection categories are omitted from the visual key but remain in the full
filter. Factual record limitations, world access, saved theme/journal/event-view
preferences and the house renderer are preserved.

## Review corrections

A fresh independent visual reviewer accepted the new palette, typography roles
and artwork framing, and requested three corrections: stack mobile insights,
remove residual relationship side accents, and resolve enlarged-text overflow.
Those corrections were implemented and recaptured. The reviewer scored all three
resolved and returned **ship** for that fix list; this is not a new whole-surface
certification.

Independent code review reproduced a new interaction between the initial dialog
scroll lock and native fullscreen exit. Replacing competing JavaScript overflow
owners with a CSS dialog lock resolved it. The exact enter-fullscreen → open
settings → exit-fullscreen → close-settings sequence is now a browser regression
check. Code review reported no outstanding material correctness findings.

## Validation

- Production TypeScript/Vite build passes.
- 601 tests across 49 Vitest files pass.
- Interface browser checks pass at 320, 390, 900 and 1440px in both themes,
  covering dialogs, insights, journal toggles, long content, hover/action/deck
  contrast, enabled-card opacity, mobile columns, event jump and scroll restoration.
- Directory checks pass at 320, 390, 1280 and 1440px: search, filters, protected
  entry links, empty/error/retry states, guide and theme persistence. Populated
  directory reflow also passes at 200% text in both themes.
- A separate 116-state rendered audit found no enabled HTML text contrast
  failures or JavaScript errors. After the final responsive corrections, 36
  enlarged-text states fit their documents and dialogs without horizontal overflow.
- Browser suites for one-tap events, appearance editing, bonds/guide, scene zoom
  and resident stacking pass. Injected Chromium touch swipe moves the deck;
  dialog-boundary wheel input leaves the document position unchanged.
- The source detector ran once on the final implementation before review fixes.
  Its palette/type advisories included stale design documentation and illustration
  values; its side-accent findings were checked against rendered rules. It was
  treated as evidence to inspect, not an accessibility or quality certification.

## Limits

Checks used deterministic local API/WebSocket fixtures in Chromium. No live
worlds, authenticated administrative mutations, physical phones, Safari/Firefox,
screen-reader sessions or production performance traces were exercised. Text
was enlarged through computed font-size scaling; this is not automated browser
UI zoom. Scene SVG labels and domain illustration colors were outside the HTML
contrast sweep. Legacy component styling still exists below the explicit shared
layers; this overhaul does not claim that every historical literal is removed.
